# AgriTech platform guide

This document describes what was built on top of the original Farm Market skeleton so that the platform
covers all five functionalities in *Agritech Platform: Five Functionalities Guide*, plus the shared
foundations the guide asks for. It also gives a demo script, says what was verified (and how), and lists the
known gaps you should close before going live.

---

## 1. What the platform does

| # | Module (guide section) | Where in the app | What a user can do |
|---|---|---|---|
| 1 | **Market segmentation** (ML, Floyd) | Overview, Market Insights | Every farmer is placed in a segment (Subsistence → Emerging → Commercial → Export-oriented) by transparent rules on day one; the existing Floyd ML service stays in place for when there is enough marketplace data. The Overview recommends the modules that fit the segment and lists "Your next steps". |
| 2 | **Digital marketplace** | Farm Market, Disputes, Group Orders, Supplier Shop | Roles (farmer, buyer, supplier, admin) with ownership checks; listings with search, sort (price, rating, nearest), minimum-rating and verified-only filters and paging; cash-on-delivery order state machine with delivery codes and double cash confirmation; stock reserved safely; **disputes** with 48-hour response window, evidence (encrypted vault files), admin decisions that move the order correctly, automatic escalation; buyer reliability score; seller **Verified business** and **Export-ready** badges; group orders with deadlines, safe concurrent joins (no overshoot), close/expire with member notifications. |
| 3 | **Farm business-building companion** | Business Builder | 3-minute intake → a personalised checklist (CIPC, SARS, VAT, banking, UIF/COIDA, permits, water use, records, business plan) generated by a rules engine; status, notes and proof documents per step; compliance calendar with SA deadlines (CIPC annual return, provisional tax, VAT201, EMP201, COIDA) and document expiry; reminders 30/7/1 days before; crop plan with a 12-month cash-flow projection, printable and Excel; admin business verification. |
| 4 | **PPECB export readiness** | Export Readiness | Requirements database tagged by authority (PPECB, Dept. of Agriculture/DALRRD, SARS Customs, destination country, buyer/private standard) for oranges, avocados and butternut to the EU, UK and SADC; 8-stage workflow; readiness score; stage gates with blockers; "who does what" view by authority; printable plan; auto-tick from the vault and Business Builder; change alerts that wait for **human review** before farmers are notified. |
| 5 | **Expense analysis with OCR + AI** | Expense Analysis, My Finances | Upload CSV, PDF, scan or photo → extract (text layer or Tesseract OCR) → parse → **balance check** (opening + transactions = closing) → categorise (learned memory → SA merchant rules → Naive Bayes on your history → optional local AI) with confidence and "needs review" → farm-sale matching with Farm Market orders → duplicates and unusual amounts (robust z-score) → review table with "apply to same merchant" → import into My Finances → analysis: monthly cash flow, spend by category, **cost per crop and per hectare** (direct + split rules), insights, CSV/Excel export and a printable **lender report**. Consent is recorded first (POPIA) and the original file is discarded unless the farmer chooses to keep it. |

Shared foundations (guide section 7): profiles and RBAC, encrypted **document vault**, append-only **audit log**,
**notifications** (in-app live via Server-Sent Events, plus email, SMS and WhatsApp when configured) with
preferences, **low-connectivity** support (installable PWA, offline banner, offline read cache, data-light pages),
**languages** (English, Afrikaans, Sepedi, Xitsonga, isiZulu), **security** (refresh-token rotation with reuse
detection, password reset, login rate limiting, TOTP two-step sign-in, security headers, admin-only actuator),
and **POPIA** (consent records with versions, data export, deletion requests and anonymisation).

## 2. Architecture

```text
React + Vite PWA (frontend/)
   │  REST + JWT (30 min) / refresh token (14 days)        Server-Sent Events (/api/live/stream)
   ▼
Spring Boot 4 API (src/)
   ├─ farmer, security ........ accounts, roles, auth, MFA, password reset
   ├─ marketplace ............. listings, orders, reviews, disputes, prices
   ├─ grouporder, supplier .... collective buying, supplier catalogues
   ├─ finance ................. ledger, monthly totals, Excel export
   ├─ companion ............... intake, rules engine, checklist, calendar, crop plan, reminders
   ├─ exportready ............. requirements DB, workflows, readiness, change review, source monitor
   ├─ statements .............. parser, categoriser, analyser, review, ledger import
   ├─ vault ................... AES-256-GCM encrypted documents with expiry
   ├─ notification ............ in-app + live + email/SMS/WhatsApp delivery
   ├─ privacy, admin, insights  POPIA, admin console, segments + next steps
   └─ common .................. audit log, roles, rate limiter, paging, config
   │
   ├──► PostgreSQL (schema managed by Flyway: V1 … V6)
   ├──► document-service (Python FastAPI: pdfplumber + Tesseract OCR) — internal only
   ├──► segmentation-service (Floyd ML), langchain-service + Ollama (optional AI)
   └──► Open-Meteo (weather, called from the browser)
```

Key design choices:

- **Flyway owns the schema** (`src/main/resources/db/migration`). Hibernate only validates (`ddl-auto=validate`).
  `V1` is a baseline that matches the old schema exactly, so existing databases are adopted with
  `baseline-on-migrate` and fresh databases are created from scratch. New foreign keys on old tables are added
  `NOT VALID` so legacy rows never block a deploy.
- **Pure, unit-tested logic** is kept apart from Spring: `StatementParser`, `TransactionCategorizer`,
  `ExpenseAnalyzer`, `CompanionRules`, `CashflowProjector`, `ExportReadiness`, `Totp`, `VaultCrypto`,
  `SimpleXlsxWriter`, `RateLimiter`.
- **Regulatory content is data, not code.** Business Builder steps and export requirements live in tables,
  carry `review_status` (DRAFT/VERIFIED) and `last_verified`, and are edited in the admin console. Every
  edit creates a new version and notifies affected farmers.
- **Notifications are sent after commit**, so nobody is told about something that rolled back.
- **No new npm dependencies** in the frontend: charts are plain SVG, printing uses the browser.

## 3. Running it

```bash
cp .env.example .env          # then set APP_JWT_SECRET; for a demo also APP_DEMO_SEED=true
docker compose up --build
```

- App: http://localhost:3000 · API: http://localhost:8080 · API docs (Swagger): http://localhost:8080/swagger-ui.html
- `document-service` starts automatically (port 8003, internal). Without it, CSV statements still work; PDFs and photos need it.

7. **Settings:** language switch, alert channels, two-step sign-in set-up, download my data.
8. On a phone: "Add to home screen" installs the app; turn on aeroplane mode to see the offline banner and cached pages.

Background jobs: reminders (06:00), dispute escalation (08:00), group-order expiry (every 10 min),
expired-token clean-up, optional source monitor.

## 5. What was verified, and how

The build environment used to produce this release had **no access to Maven Central, npm or PyPI**, so the
usual `mvn verify` and `vite build` could not be run there. Instead:

| Check | Result |
|---|---|
| Whole backend compiled with `javac` against API stubs of Spring/JPA/Jakarta | 0 errors |
| Pure-logic JUnit tests (parser, categoriser, analyser, rules engine, cash-flow, TOTP, vault crypto, xlsx, rate limiter, export readiness) run with a JUnit-compatible runner | 25 / 25 pass |
| All Flyway migrations on a fresh PostgreSQL database and on a copy of the old schema | pass |
| Every JPA entity compared column-by-column with the migrated schema (emulating `ddl-auto=validate`) | 41 entities, 0 problems |
| document-service tests (PDF text layer, OCR of a scan and a phone photo) | 4 / 4 pass |
| End to end: sample PDF → document-service → Java parser → categoriser | balance PASSED, categories correct |
| Frontend bundled with esbuild (catches syntax errors, bad imports and missing exports) | pass |
| Frontend unit tests (`npm test`) | 8 / 8 pass |
| Pages rendered in headless Chromium against a mock API, desktop and phone widths | no runtime errors |

**First thing to do on your machine:** `./mvnw verify` and `cd frontend && npm ci && npm run build && npm test`.
If anything fails, it is most likely one of the risks below.

## 6. Known risks and next steps

1. **Dependency names on Spring Boot 4.** The build uses `spring-boot-starter-flyway`, `flyway-database-postgresql`,
   `spring-boot-starter-mail` and `springdoc-openapi-starter-webmvc-ui` **3.0.0**. If Maven cannot resolve one of them,
   adjust the artifact or version in `pom.xml` (for example, use the latest springdoc 3.x).
2. **Regulatory content is DRAFT.** About 30 Business Builder steps and 33 export requirements were written from
   public sources but have **not been checked by a professional**. Have an export agent / PPECB contact and a tax
   practitioner review them in *Admin → Content*, then mark them verified. Farmers see "Draft" until then.
3. **Translations are drafts.** Afrikaans, Sepedi, Xitsonga and isiZulu strings need a first-language reviewer
   (see `frontend/src/lib/i18n.js`).
4. **Bank formats.** The parser was tested with FNB/Capitec/TymeBank-style CSVs and generic PDF layouts. Collect a
   few real (anonymised) statements from Standard Bank, Absa and Nedbank and add them as tests.
5. **Integration tests.** Add Spring Boot tests with Testcontainers for the order, dispute and statement flows,
   and Playwright end-to-end tests for the demo script.
6. **Production settings.** Set a separate `APP_VAULT_KEY` and back it up; configure SMTP (and SMS if wanted);
   keep `APP_DEMO_SEED` and `APP_DEV_SHOW_RESET_LINK` off; `SPRINGDOC_ENABLED=false`; serve over HTTPS
   (`docker-compose.https.yml`).
7. **Legal.** Have the terms of use and privacy notice drafted by a lawyer; register an Information Officer with
   the Information Regulator (POPIA).
